# IPv4 VLSM 地址规划台

本地运行的 IPv4 可变长子网掩码（VLSM）地址规划工具。基于 **React 18 + TypeScript + Vite**，纯前端计算，数据不离开本机。

## 功能

- **录入父 CIDR**（如 `192.168.10.0/24`）。
- **保留区**：以 CIDR 形式录入，不参与需求分配。
- **需求列表**：每项填写「主机数」和**可选**的固定网段（CIDR）。
- **自动网段容量**：按「可用主机数 = 地址数 − 2」（扣除网络地址与广播地址）取最小 2 的幂分块，**最小为 /30**（4 个地址、2 个可用主机）。
- **校验规则**：
  - 保留区和固定网段必须完全位于父网段内；
  - 保留区与固定网段之间、以及彼此之间**互不重叠**；
  - 固定网段的可用主机数必须足够容纳该需求，否则报错并给出实际可用数。
- **分配算法**：自动需求按规模**从大到小**排序，同规模按**录入顺序**，在保留区/固定网段/已分配网段之外选取**最低的、满足前缀边界对齐**的空闲块；放不下时在页面上说明原因（最大连续空闲块大小 / 对齐不满足）。
- **比例地址条**：按地址数比例区分 🟠 保留、🟣 固定、🟢 自动、⚫ 空闲四类区域。
- **点击交互**：点击地址条色块或明细表任意行，展示该项的**网络地址、广播地址、可用范围、容量与浪费量**。
- **基线对比**：把当前无输入错误的规划保存为基线，修改后按需求的稳定 ID 比较新旧结果。
- **路由汇总**：勾选当前成功分配的固定 / 自动网段，将所选地址并集汇总为**数量最少且覆盖精确**的 CIDR 列表，逐条展示地址数与覆盖的原需求，支持一键复制按网络地址升序排列的纯 CIDR 列表。
- **主机地址分配**：为成功分配的固定 / 自动网段登记设备名与单个 IPv4 主机地址，支持「自动取首个未占用可用地址」或手动输入；强制跳过网络 / 广播地址，拒绝越界、重复或已占用地址，并实时显示每个网段的剩余可用数。每条登记可录入 / 修改 **MAC 地址**（接受冒号或连字符分隔的六组两位十六进制，自动规范为小写冒号；拒绝全零、组播位与跨设备重复）。重新规划后按需求稳定 ID 保留仍合法的登记，失效登记明确标记且**绝不静默改址**。
- **dnsmasq 静态租约**：在主机地址分配面板底部实时生成 `dhcp-host=<MAC>,<IPv4>` 配置，只纳入当前规划中**有效且具备合法 MAC** 的登记，按 IPv4 升序排列；失效或缺失 MAC 的条目列出原因但不输出，支持一键**复制**与**下载 .conf**。
- **DHCP Option 121（无分类静态路由 / RFC 3442）**：选择一个当前成功分配的固定 / 自动网段作为**客户端网段**，录入多条「目的 CIDR + 下一跳 IPv4」。目的须为规范网络地址（允许 `0.0.0.0/0` 默认路由），下一跳必须是客户端网段内的可用主机地址；按**目的前缀从长到短、网络地址升序**生成 RFC 3442 字节（前缀长度后仅写 `ceil(前缀/8)` 个目的网络字节，再写四个下一跳字节），逐条展示十进制字节并合并为 `dhcp-option=121,...` 配置，支持一键**复制**与**下载 .conf**。重复目的或任一无效条目都会明确定位（按录入序号）并停止整体生成；规划变化后按稳定 ID 保留录入并自动重新校验，客户端网段失效时暂停结果且录入不丢失。
- **反向 DNS 区域文件（in-addr.arpa / RFC 2317）**：选择一个当前成功分配的固定 / 自动网段，读取其中当前**有效**且设备名为**合法绝对域名**的主机登记。`/24` 生成标准反向区域的 PTR 记录；`/25～/30` 按 [RFC 2317](https://datatracker.ietf.org/doc/html/rfc2317) 为每条登记生成**父区域 CNAME 片段**与**子区域 PTR 文件**两段文本，子区域以网段起止末位命名（如 `16-19.10.168.192.in-addr.arpa`）。结果按 IP 升序预览，支持分别**复制**与**下载区域文件**；单标签设备名（如「网关」）跳过，重复域名或不合法名称逐条报错并停止整体生成；网段迁移、登记增删或改址后实时重算，且只读规划与登记、不修改任何既有数据。
- **DHCP 动态地址池（dnsmasq dhcp-range）**：选择一个当前成功分配的固定 / 自动网段，录入多段**手工排除区间**（起始 ~ 结束，结束留空表示仅排除单地址）。模块自动排除该网段的**网络地址、广播地址**及**当前有效的主机登记**；手工区间**重叠或相邻先合并**，剩余地址按连续区间生成 `dhcp-range=<起始>,<结束>,<点分掩码>` 配置。排除区间必须完全位于所选网段且起止有序，任一无效条目都会按录入序号明确定位并停止整体生成。逐段展示**可分配数量与总数**，支持一键**复制**与**下载 .conf**；规划、登记或排除项变化后实时重算，宿主网段失效时暂停输出但保留网段选择与全部录入。
- **基线优先重排模式**：已保存基线且父网段与基线完全一致时可开启。为每个基线自动需求按当前主机数计算目标前缀，把**包含其原网络地址的对齐块**作为优先候选；候选越界、撞保留区或固定段、与其他候选冲突时，按所需地址数**从大到小、同规模按录入顺序**保留可行候选，其余需求再用既有最低对齐策略分配。结果逐条标明**保留原址 / 迁移 / 兜底落位 / 无法分配（含候选不可行原因）**；父网段变化或无基线时开关禁用，关闭后立即恢复原算法。基线对比、路由汇总与主机登记全部随重排结果联动。
- **静态租约批量导入**：粘贴**含表头**的 CSV（列为「网段 CIDR、设备名、IPv4、MAC」，列顺序不限、支持常见别名），实时生成逐行预览。网段 CIDR 必须**唯一匹配**当前成功分配的固定或自动网段；MAC 规范化（小写冒号）后作为**设备身份**——已有 MAC 更新名称、网段与地址，新 MAC 新增。应用前先构造「现有登记 + 本次导入」的**合并完整快照统一校验**（两台已有设备互换地址不会因处理顺序误报），逐行标记**新增 / 更新 / 无变化 / 冲突**；可识别缺失或非法字段、输入内重复 MAC、网段内重复 IP、网络地址 / 广播地址 / 越界地址以及与未更新登记的冲突。**任一冲突即禁止应用**，全部通过后一次性替换主机登记状态。原始 CSV 始终保留，规划变化后预览实时重算。
- **迁移执行编排**：复用静态租约批量导入的**现有登记与无冲突 CSV 合并预览**（不应用也能预览），以旧地址占用关系建立依赖图，生成按序执行时**不会产生瞬时重复 IPv4** 的逐步改址清单。无环依赖按「目标地址最低优先」的可执行顺序输出；**互换或多设备环路**先把环中一台设备迁到其**原网段内最低的临时可用地址**（候选排除全部当前占用与全部目标地址，并避让其他环路已选临时地址），再依次完成环路、最后把该设备从临时地址迁到目标并**释放临时地址**；环中任何设备都找不到临时地址（如满配 /30 互换）时**明确阻止该环且不产生任何步骤**。逐步展示设备、原 / 目标 / 临时地址、目标网段与每步原因，支持一键**复制清单**（制表符分隔）。新设备在目标地址腾空后上线；目标地址被不会迁走的既有（含失效）设备物理占住时点名阻止。CSV、规划或登记任意变化实时重算；**冲突预览不生成结果且不改动登记**。
- **IPv4 路径分片预演**：从**当前有效主机登记**选择发送设备，输入负载字节数（1～65515）、**DF 开关**与按经过顺序排列的 **1～8 跳 MTU**（68～65535 整数），固定 IPv4 首部 20 字节、无选项，**仅本地计算**。每跳处理上一跳全部分片：不超 MTU 原样通过；超 MTU 且 DF=1 时报告**首个阻断跳**并停止；DF=0 时取不超过 MTU 的最大负载拆分，除原始最后一片外负载均为 **8 的倍数**。后续跳可再次分片但**绝不重组**；片偏移始终相对原始负载、以 8 字节计，MF 仅在该片之后仍有原始数据时为 1。逐跳展示各片**负载范围、总长度、偏移量与 MF**，并统计**片数与首部开销**（片数 × 20 字节）。输入非法（精确定位字段与跳序）或设备失效时**保留选择与全部输入并暂停**；登记或规划变化实时重算。
- **导出 JSON**：一键导出包含父网段、统计、全量网段明细及失败原因的 JSON 文件（时间戳命名）；开启重排时附带重排统计与逐需求明细。

## 快速开始（Docker Compose，一条命令）

```bash
docker compose up -d --build
```

启动后浏览器访问：

> **http://localhost:8080**

打开页面后向下滚动即可看到各功能面板，DHCP 动态地址池模块入口为 **⑨ DHCP 动态地址池（dnsmasq dhcp-range）**（紧随 ⑧ 反向 DNS 区域文件之后），**⑩ 静态租约批量导入**位于其下；**⑪ 迁移执行编排**紧随 ⑩ 批量导入（直接复用 ⑩ 的 CSV 合并预览，无需应用即可生成改址清单）；页面最底部为 **⑫ IPv4 路径分片预演**（从有效主机登记选择发送设备，逐跳模拟 RFC 791 分片）。本地开发模式下访问地址为 http://localhost:5173。

停止：

```bash
docker compose down
```

> 端口占用时修改 `docker-compose.yml` 中的 `"8080:80"`，例如改为 `"9090:80"`。

| 办公区 VLAN | 100 | | 自动（128/25，126 可用） |

## 基线对比（按稳定 ID）

页面 **④ 基线对比** 面板提供「保存 → 修改 → 对比」工作流：

1. **保存基线**：当前规划没有输入错误时，点击「保存当前规划为基线」。基线包含父网段、每个需求（成功分配的网段与失败原因）和全部占用地址区间。
2. **修改输入**：调整父 CIDR、保留区或需求。每条需求在添加时获得一个**稳定 ID**，改名、改主机数或换固定网段都保持同一 ID，因此对比不依赖名称。
3. **查看对比**：面板与「网段明细」表实时刷新，每个需求归入下列状态之一：

   | 状态 | 含义 |
   | --- | --- |
   | 🟢 新增 | 基线保存后新添加的需求 |
   | 🔴 删除 | 基线中存在、当前列表已删除的需求 |
   | ⚪ 未变 | 网段 CIDR 与容量均未变 |
   | 🟡 扩容 / 缩容 | 容量变化（CIDR 改变时同时标记迁移） |
   | 🔵 迁移 | 网段 CIDR 改变即视为迁移；容量同时变化时叠加「扩容/缩容」标记 |
   | 🔴 未分配 | 基线时已分配、当前因空间不足等原因分配失败 |
   | 🟢 恢复分配 | 基线时分配失败、当前已成功分配 |
   | ⚪ 仍未分配 | 两个时点都分配失败（附当前失败原因） |

4. **地址区间汇总**：按地址区间列出
   - **新占用**（基线空闲 → 当前占用）、**释放**（基线占用 → 当前空闲）、**仍占用**（两个时点都占用）；
   - 区间自动合并去重，重叠地址**不重复计数**，满足「新占用 + 仍占用 = 当前占用」「释放 + 仍占用 = 基线占用」；
   - **净地址变化 = 新占用 − 释放**（正数表示占用增加）；
   - 变化地址条用 🟩 新占用 / 🟥 释放 / ▫️ 仍占用 三色按比例展示，悬停可看具体区间。
5. **清除 / 重建**：「清除基线」立即移除（同时删除会话存储）；「重建基线」用当前规划覆盖旧基线。
6. **输入非法时**：基线予以保留，面板显示暂停提示并停止对比；输入修正后自动恢复，无需重新保存。

> 基线仅保存在**当前浏览器会话**（`sessionStorage`）：刷新页面仍在，关闭标签页或浏览器后自动消失；不上传任何服务器。

## 基线优先重排模式

面板 **④ 基线对比** 顶部提供「**基线优先重排**」开关。普通算法在输入变化后会把全部自动需求重新从低地址摆放（哪怕该需求原址仍然空闲），本模式则尽量让已有需求留在基线时的位置：

1. **启用条件（任一不满足开关禁用并提示原因）**：
   - 已保存基线（无基线时先保存）；
   - 当前父网段为**规范 CIDR 且与基线父网段完全一致**——父网段变化时模式禁用（地址数值空间不同，原址无意义）；
   - 左侧输入无错误。开关状态保留在页面内存中；条件恢复后可再次开启，**清除基线会自动关闭**。
2. **目标前缀与优先候选**：对每条在基线中**成功分配的自动需求**（按稳定 ID 匹配），按**当前主机数**用同一口径（`地址数 − 2 ≥ 主机数`，最小 /30）计算目标前缀；该前缀下**唯一**包含其原网络地址的边界对齐块即为优先候选。
3. **候选筛选（贪心保留可行候选）**：候选按所需地址数**从大到小**排序、同规模按**录入顺序**，依次保留满足下列全部条件者，并立即占位供后续候选感知——
   - 整块位于父网段内（不越界）；
   - 不与任何保留区、用户固定网段重叠；
   - 不与已被保留的其他优先候选冲突（含原基线地址空间相互重叠的情形）。
   不可行候选记录具体原因（`对齐块 x 越出父网段` / `与保留区…冲突` / `与…固定网段冲突` / `与已保留原址的需求…候选块冲突`）。
4. **其余需求**：候选被拒的需求、基线后新增的需求、基线时未分配或固定↔自动转换的需求，统一再走**既有最低对齐策略**（规模从大到小、同规模按录入顺序）。
5. **结果标注**（顶部统计横幅 + 明细表「基线重排」列 + 面板明细表）：

   | 结果 | 含义 |
   | --- | --- |
   | 🟢 保留原址 | 优先候选被采纳，且当前 CIDR 起点与基线原址相同（含原地缩容） |
   | 🔵 原址迁移 | 优先候选被采纳，但新前缀的对齐块起点已不同于基线原址（原址容纳不下更大前缀时块仍包含原址） |
   | 🔵 兜底保留 / 兜底迁移 | 优先候选不可行，由最低对齐策略落位（恰好落回原址 / 迁移到新址），徽标注明「最低对齐」 |
   | 🔴 无法分配 | 候选与最低对齐均失败；失败原因以「基线优先候选 x 不可行：…」开头并附当前空闲块情况 |
   | ⚪ 固定段 / 转为固定 / 固定转自动 / 基线时未分配 | 不参与重排的各类情形，逐条说明 |
   | 🟣 新增需求 | 基线中不存在，直接走最低对齐策略 |

6. **联动**：重排结果就是新的 `PlanResult`——**基线对比**按同一稳定 ID 比较（原址保留的需求显示「未变」）、**路由汇总**列出重排后的固定/自动网段、**主机登记**按重排后网段重新校验（原址保留则设备地址继续有效，迁移/失败照旧明确标记且绝不静默改址）、Option 121 与 dnsmasq 租约同步重算、**导出 JSON** 附带「基线优先重排」统计与明细。
7. **关闭即恢复**：关闭开关后同一份输入立即按原算法重新计算（字节级一致），不留任何残留状态。

## 路由汇总

页面 **⑤ 路由汇总** 面板用于把多条已规划网段汇总成便于下发路由（如静态路由 / OSPF 汇总）的精简 CIDR 列表：

1. **勾选网段**：列表只包含当前**成功分配**的固定、自动网段（带类型徽标与各自 CIDR）。可单选、多选或「全选 / 全不选」。
2. **汇总算法**：先把勾选网段的地址区间**合并相邻区间**，再对每个连续区间**按地址对齐边界贪心拆分**为 CIDR（每一步取起点可对齐的最大 2 的幂块）。因此：
   - 结果 **CIDR 数量最少**，并集与所选地址**严格相等**（不多一个、不少一个）；
   - **只有同前缀、连续且同属一个上级网段**的两个块才会被聚合（例如同属一个 `/29` 的两个 `/30` 聚合成 `/29`；`4/30` 与 `8/30` 虽连续但上级 `/29` 不同，则不聚合）；
   - 任何汇总项都**不包含未选需求、保留区或空闲地址**（区间不相邻就绝不跨越）。
3. **结果展示**：逐行列出汇总 CIDR、地址数以及它覆盖的**原始需求名称与网段**；由多段聚合而成的行带「聚合」标记；顶部给出「已选网段数 / 地址总数 → CIDR 数」。
4. **一键复制**：点击「📋 复制 CIDR 列表」复制**按网络地址升序**排列的纯 CIDR（每行一个），适合直接粘贴进路由配置；复制成功有「✓ 已复制」反馈。
5. **禁用与自动清理**：输入非法或没有成功分配的网段时整个面板禁用并提示原因；规划变化后，已删除或分配失败的网段会自动从勾选中移除（同一需求 ID 重新成功分配时其勾选保留）。

> 汇总只读取当前规划结果，全部在浏览器本地完成。

## 主机地址分配

页面 **⑥ 主机地址分配** 面板用于在已规划好的固定 / 自动网段内逐台登记设备（登记不影响规划结果本身）：

1. **可登记网段**：仅列出当前**成功分配**的固定、自动网段（带类型徽标、CIDR 与可用范围）；保留区、空闲区与分配失败的需求不出现。输入非法时整个面板暂停并保留全部登记。
2. **添加设备**：填写设备名称后二选一——
   - **⤓ 自动取址**：取该网段**第一个未占用的可用主机地址**（始终从 `网络地址+1` 起扫描，自动跳过网络地址、广播地址与已登记地址）；
   - **手动输入 IPv4**：直接填写地址后「＋ 添加」（输入框中按回车等效）。
   - 两者均可在添加时选填 **MAC 地址**，也可添加后随时补录 / 修改。
3. **校验规则（手动输入逐条拒绝并给出原因）**：
   - IPv4 不是合法文本；
   - 是**网络地址**或**广播地址**（即使数值在网段区间内也拒绝）；
   - **不在所属网段**的可用范围内（含属于父网段内其他网段的地址）；
   - 与同网段已有登记**重复 / 已占用**（提示占用设备名）。
4. **MAC 校验规则**：
   - 接受**冒号**（`aa:bb:cc:dd:ee:ff`）或**连字符**（`AA-BB-CC-DD-EE-FF`）分隔的六组两位十六进制，自动统一为**小写冒号**格式（分隔符不可混用，不接受点分写法 `aabb.ccdd.eeff`）；
   - 拒绝**全零** `00:00:00:00:00:00`；
   - 拒绝首字节最低位为 1 的**组播地址**（含广播 `ff:ff:ff:ff:ff:ff`）；
   - 拒绝与**其他任何设备**重复（全局去重、不限网段；MAC 大小写与分隔符归一后比较），编辑自身保留原值不算重复。
5. **剩余可用数**：每个网段标题实时显示「剩余可用 X / 可用主机总数（已登记 Y）」，剩余为 0 时高亮且禁止新增；失效登记不占用剩余数。
6. **改址、改 MAC 与删除**：每条登记可随时「改址」（手动输入并走同一套校验，地址变化后自动标记为「手动」，Esc 取消、回车保存）、点击 MAC 单元格**录入 / 修改 MAC**（留空保存即清除），或「删除」。
7. **重新规划后的稳定性（按需求稳定 ID）**：规划重新计算后，面板按需求 ID 重新校验每条登记——
   - 地址仍在所属网段可用范围内且不重复：**原样保留**（自动取址得到的地址也不会被重新分配或静默改写）；
   - 网段迁移 / 改掩码导致地址越界、成为新网络地址或广播地址、与其他登记重复：登记保留在原网段分组顶部，地址加删除线并标记**不在网段 / 网络地址 / 广播地址 / 重复**及具体原因；
   - 所属需求被删除或当前分配失败：登记收入面板顶部的「失效登记」区（原因分别为需求已删除 / 分配失败），地址保持原样，只能手动删除或通过调整规划使其恢复；
   - 面板顶部提供「清除全部失效登记」批量操作。
8. **边界**：主机登记（含 MAC）只保存在当前页面内存中（载入示例 / 清空会一并清除），**不写入**规划、基线、路由汇总与 JSON 导出；这些功能的输入、算法与输出均不受登记影响。

### dnsmasq 静态租约

主机地址分配面板底部的「**dnsmasq 静态租约（dhcp-host）**」区随规划与登记实时重算：

1. **纳入条件**：仅输出当前规划中**有效**（地址仍合法、未重复）且**填写了合法 MAC** 的设备登记；
2. **排除但可见**：失效登记（需求删除 / 分配失败 / 越界 / 网络地址 / 广播地址 / 地址重复）与未填写 MAC 的登记**不进入输出**，在「未输出条目」表中逐条列出设备、IPv4、MAC 与原因；
3. **输出格式**：按 **IPv4 升序**排列，每行

   ```
   dhcp-host=<MAC>,<IPv4>
   ```

   例如 `dhcp-host=00:11:22:33:44:55,192.168.10.17`，可直接追加到 dnsmasq 配置（如 `/etc/dnsmasq.d/dhcp-host.conf`）后重启 / 重新加载 dnsmasq；
4. **复制与下载**：「📋 复制」把全部租约行写入剪贴板（含复制成功反馈）；「⬇ 下载 .conf」下载时间戳命名的 `dnsmasq-dhcp-host-<时间戳>.conf` 文件；没有可输出条目时两个按钮禁用；
5. **实时性与隔离**：规划或登记任意变化（改址、改 MAC、增删设备、网段迁移等）后输出立即重算；该功能**只读**规划与登记，不修改规划、基线、路由汇总与 JSON 导出。

## DHCP Option 121（无分类静态路由）

页面 **⑦ DHCP Option 121** 面板按 [RFC 3442](https://datatracker.ietf.org/doc/html/rfc3442) 为某个客户端网段生成 dnsmasq 的 `dhcp-option=121` 无分类静态路由配置（生成过程不影响任何既有功能）：

1. **选择客户端网段**：下拉框只列出当前**成功分配**的固定、自动网段（带类型徽标、CIDR 与可用范围）；保留区、空闲区与分配失败的需求不出现。下一跳（网关）必须落在该网段的**可用主机范围**内。
2. **录入路由条目**：每条包含——
   - **目的 CIDR**：必须是**规范网络地址**（主机位全 0），允许默认路由 `0.0.0.0/0`；输入非规范地址（如 `192.168.1.5/24`）会报错并提示正确写法（`192.168.1.0/24`）；
   - **下一跳 IPv4**：必须是合法 IPv4，且位于客户端网段的可用主机范围（`网络地址+1 … 广播地址−1`）内；网络地址、广播地址与范围外地址一律拒绝，错误信息给出该网段的可用范围；
   - **目的必须唯一**：重复的规范目的 CIDR 从第二条起报错，并指明与第几条重复。
3. **RFC 3442 编码**：每条路由编码为——

   ```
   <前缀长度> <目的网络的前 ceil(前缀/8) 个字节> <下一跳的 4 个字节>
   ```

   即前缀长度之后**只写目的网络最高若干字节**（`/24` 写 3 字节、`/8` 写 1 字节、`/0` 写 0 字节、`/32` 写 4 字节），再固定写四个下一跳字节。所有条目按 **目的前缀从长到短（更具体优先）、网络地址升序**排列后拼接。
4. **结果展示**：每条录入（无自身错误时）在行内实时显示其十进制字节；全部有效时，结果区按下发顺序表格列出「下发序 / 目的 CIDR / 下一跳 / 本条十进制字节」（并标注对应录入序号），并给出**合并字节**与 dnsmasq 配置行：

   ```
   dhcp-option=121,24,192,168,1,192,168,10,17,0,192,168,10,17
   ```

   可直接追加到 dnsmasq 配置（如 `/etc/dnsmasq.d/option121.conf`）后重新加载。
5. **错误定位与整体停止**：重复目的或任何一条无效（非法文本、非规范网络地址、缺字段、下一跳不可用等）都会在错误清单中**按录入序号逐条列出**，对应行高亮；此时**停止整体生成**——不输出合并字节与 `dhcp-option=121` 配置（无自身错误的行仍逐行预览字节，便于修正）。
6. **复制与下载**：「📋 复制」复制完整配置行（含「✓ 已复制」反馈，非安全上下文自动回退）；「⬇ 下载 .conf」下载时间戳命名的 `dnsmasq-dhcp-option121-<时间戳>.conf`；存在错误或没有有效条目时按钮禁用。
7. **规划变化后的稳定性**：客户端网段与全部路由录入均以**稳定 ID**（需求 ID / 行 ID）保存在页面内存中——
   - 重新规划后录入原样保留并**自动重新校验**：网段迁移、改掩码后下一跳可能变为越界 / 网络 / 广播地址，会即时标出而绝不静默改写；
   - 所选客户端网段被删除或分配失败时，面板顶部提示**结果已暂停**，录入与选择全部保留；重新选择（或该需求恢复分配）后自动恢复生成；
   - 输入非法（左侧规划错误）时同样暂停结果、保留全部录入。
8. **边界与隔离**：Option 121 的选择与录入**不写入**规划、基线、路由汇总、主机登记与 JSON 导出；这些模块的输入、算法与输出在有无 Option 121 数据时严格一致。载入示例 / 清空会一并清除本面板状态。

## 反向 DNS 区域文件（in-addr.arpa / RFC 2317）

页面 **⑧ 反向 DNS 区域文件** 面板为所选网段生成反向解析区域文本（生成过程不影响任何既有功能）：

1. **选择网段**：下拉框只列出当前**成功分配**的固定、自动网段（带类型徽标、CIDR 与可用范围）；保留区、空闲区与分配失败的需求不出现。输入非法或所选网段失效（需求删除 / 分配失败）时暂停结果，选择保留，恢复后自动重新生成。
2. **数据来源**：读取该网段内经当前规划校验**有效**（地址仍在所属网段可用范围内、未与同网段登记重复）的主机登记，且设备名必须是**合法绝对域名（FQDN）**：
   - 合法名称示例：`gw.example.com`、`core-sw-1.site-a.example.net`、`host.example.com.`（根尾点可有可无，输出统一归一为**小写、带根尾点**）；
   - 标签规则（LDH）：每段 1–63 字符，只能含字母、数字与连字符 `-`，且必须以字母或数字开头 / 结尾（**不接受下划线**）；总长度（不含尾点）不超过 253；顶级标签不能是纯数字；不接受非 ASCII（国际域名需先做 Punycode 编码）、空格、连续点与多个尾点；
   - **单标签设备名**（如「网关」「core-sw」、空名称）视为并非域名，**静默跳过**（在预览表中标为「跳过（非域名）」），不报错、不阻断。
3. **/24 标准区域**：生成 `$ORIGIN <前 3 字节反序>.in-addr.arpa`（如 `192.168.20.0/24` → `20.168.192.in-addr.arpa`）的完整区域文件，包含 `$TTL`、SOA、NS 占位模板与每条登记一行

   ```
   1    IN  PTR   gw.example.com.
   ```

4. **/25～/30（RFC 2317）两段文本**：因 `/25`～`/30` 不是天然的 in-addr.arpa 授权边界，按 RFC 2317 生成——
   - **子区域**以网段「起始末位-结束末位」命名：如 `192.168.10.16/30`（地址 .16～.19）→ `16-19.10.168.192.in-addr.arpa`；`/25` 起点为 `0-127` 或 `128-255`；
   - **父区域 CNAME 片段**（追加进所属 /24 区域），每条登记一行，并在片段顶部注释给出对应的 NS 委派写法：

     ```
     17   IN  CNAME 17.16-19.10.168.192.in-addr.arpa.
     ```

   - **子区域 PTR 文件**（独立 zone），每条登记一行 `末位 IN PTR <域名>.`；
   - 面板对两段文本提供**各自独立**的复制与下载按钮。
5. **结果预览与排序**：表格按 **IPv4 升序**逐条列出 IPv4、设备名原文、将生成的反向记录与状态（纳入 / 跳过 / 名称错误 / 未读取）。
6. **重复域名或不合法名称：逐条报错并停止整体生成**——错误清单按该网段有效登记的 IP 顺序逐条定位（第 N 条、IPv4 与原因；重复域名指明与第几条重复，比较时忽略大小写与根尾点）；存在任一错误时**不输出任何区域文本**（无错行仍可在预览表查看）。
7. **失效登记不读取、不阻断**：网段迁移 / 改掩码导致的越界、网络地址、广播地址、重复地址等失效登记（见「⑥ 主机地址分配」）不会进入区域，只在预览表标为「未读取」并显示原因；请回到主机地址面板改址或删除。
8. **实时重算与隔离**：网段迁移、登记增删、改名或改址后由 React 记忆化**立即重算**（如 /30 从 `.16-.19` 迁到 `.20-.22` 后，原 `.17` 登记自动撤出并在新址登记后恢复输出）。本面板**只读**规划与登记，不修改规划、基线、路由汇总、主机登记与 JSON 导出。
9. **占位模板与下载**：区域文件中的 SOA / NS 为占位值（`ns.example.com.`、`hostmaster.example.com.`，序列号默认取生成当日 UTC 的 `YYYYMMDD00`），部署前请替换为实际权威名称服务器。下载为浏览器端 Blob（`.zone`，文件名含区域名与 UTC 时间戳）；复制使用剪贴板 API，非安全上下文自动回退。`/24` 之外大于 /24（如 /23）与 /31、/32 不支持，面板会说明原因。

## DHCP 动态地址池（dnsmasq dhcp-range）

页面 **⑨ DHCP 动态地址池** 面板为所选网段生成 dnsmasq 的 `dhcp-range` 动态地址池配置（生成过程不影响任何既有功能）：

1. **选择宿主网段**：下拉框只列出当前**成功分配**的固定、自动网段（带类型徽标、CIDR 与可用范围）；保留区、空闲区与分配失败的需求不出现。输入非法或所选网段失效（需求删除 / 分配失败）时暂停结果，网段选择与全部排除区间录入均保留，恢复后自动重新生成。
2. **自动排除**（无需手工填写）：
   - 网段的**网络地址**与**广播地址**——候选空间恒为可用主机范围 `网络地址+1 … 广播地址−1`，即使手工区间覆盖网络 / 广播地址也不会额外占用可分配数量；
   - 该网段内**当前有效的主机登记**（来自「⑥ 主机地址分配」）；失效登记（越界 / 网络 / 广播 / 重复 / 孤儿）不参与、不阻断，面板会列出实际被自动排除的登记地址与设备名。
3. **录入手工排除区间**：每行填写「起始 IPv4 ~ 结束 IPv4」——
   - **结束留空**表示仅排除起始**单地址**（适合预留网关、个别服务器等）；
   - 两端必须是合法 IPv4、**完全位于所选网段**内（含网络 / 广播地址本身时合法，但不产生额外扣除），且**起止有序**（结束不得小于起始）；
   - 起始与结束均为空白的占位行不参与校验。
4. **重叠 / 相邻先合并**：多段手工排除区间重叠或首尾相邻时自动合并去重（与有效登记地址重叠也一并合并），同一地址绝不重复扣除；面板以标签形式展示合并后的排除区间。
5. **结果展示**：剩余地址按**连续区间**分段，表格逐行列出「段序 / 起始 / 结束 / **本段可分配数量** / 配置行」，页脚给出**可分配总数**与分段数；顶部同时展示网段、点分掩码、可用主机范围、自动排除的登记数与合并后的手工区间数。全部可用地址都被排除时明确提示「暂无可分配地址」。
6. **输出格式**：每段一行（掩码为宿主网段前缀对应的点分十进制掩码，如 `/27` → `255.255.255.224`）

   ```
   dhcp-range=192.168.10.33,192.168.10.39,255.255.255.224
   dhcp-range=192.168.10.42,192.168.10.62,255.255.255.224
   ```

   可直接追加到 dnsmasq 配置（如 `/etc/dnsmasq.d/dhcp-range.conf`）后重新加载。
7. **错误定位与整体停止**：任何一条区间无效（非法 IPv4、越出网段、起止颠倒、缺起始等）都会在错误清单中**按录入序号逐条列出**（越界行的起止分别报错），对应行高亮；此时**停止整体生成**——不输出任何地址池与配置行（无自身错误的行仍逐行预览其区间，便于修正）。
8. **实时重算**：规划调整（网段迁移 / 改掩码）、主机登记增删改址、排除区间增改删后由 React 记忆化**立即重算**；网段迁移后原录入自动按新网段重新校验（越界即时标出而绝不静默改写），该需求恢复分配或改选有效网段后自动恢复输出。
9. **复制与下载**：「📋 复制」复制全部 `dhcp-range` 行（含「✓ 已复制」反馈，非安全上下文自动回退）；「⬇ 下载 .conf」下载 `dnsmasq-dhcp-range-<网段>-<UTC 时间戳>.conf`；存在错误或没有可分配地址时按钮禁用。
10. **边界与隔离**：网段选择与排除录入**不写入**规划、基线、路由汇总、主机登记与 JSON 导出；上述模块的计算结果在有无本面板状态时严格一致。载入示例 / 清空会一并清除本面板状态。

## 静态租约批量导入

页面底部 **⑩ 静态租约批量导入** 面板用于把一批静态租约（设备名 + IPv4 + MAC）按网段一次性并入「⑥ 主机地址分配」的登记（导入过程本身只读规划与登记，应用后才整体替换登记状态）：

1. **CSV 格式**：粘贴**含表头**的 CSV 文本，必需四列为 **网段 CIDR、设备名、IPv4、MAC**；
   - 列顺序任意，表头识别常见别名（如 `cidr/子网`、`名称/hostname`、`ip地址/address`、`物理地址`），识别时忽略大小写与空白；
   - 支持引号包裹的字段（字段内可含逗号或换行，`""` 表示一个双引号），CRLF / LF 均可，BOM 自动去除，完全空白的行被忽略；
   - MAC 接受冒号或连字符分隔的六组两位十六进制，自动规范为小写冒号，拒绝全零与组播位（与逐台录入同一口径）。
2. **网段匹配**：网段 CIDR 必须是**规范网络地址**，且**唯一命中**当前**成功分配的固定 / 自动网段**（与规划结果中的 CIDR 完全一致）；保留区、空闲区、分配失败需求的地址以及父网段内其他网段都不能匹配。
3. **设备身份（MAC）与合并语义**：MAC 规范化后作为设备身份——
   - CSV 中的 MAC 已存在于主机登记：**更新**该设备的名称、所属网段与 IPv4 地址（登记的稳定 ID 不变）；
   - CSV 中的 MAC 不存在：作为**新增**登记；
   - 名称、网段、地址与现状完全一致的行标记为**无变化**。
4. **统一快照校验（顺序无关）**：应用前先构造「未被 CSV 命中的既有登记 + 全部导入行」的**合并后完整登记快照**，再一次性校验。因此即使两台已有设备在 CSV 中**互换地址**（A→原 B 的地址、B→原 A 的地址），无论两行先后顺序如何都不会被误报为地址冲突；只有真正与**未更新登记**相撞才算冲突。
5. **逐行预览与冲突识别**：每行标记 🟢 **新增** / 🔵 **更新** / ⚪ **无变化** / 🔴 **冲突**，冲突行逐条列出原因，包括——
   - 缺失字段（网段 / 设备名 / IPv4 / MAC 任一为空）；
   - 非法字段（CIDR 文本非法或非规范、IPv4 非法、MAC 格式非法 / 全零 / 组播位）；
   - 网段不匹配（不是当前成功分配的固定或自动网段）；
   - 地址是**网络地址 / 广播地址**，或**越出**该网段可用主机范围；
   - **输入内重复 MAC**（规范化后比较，指明首次出现的数据行号）；
   - **网段内重复 IP**（同一网段两个地址相同；不同网段同址允许）；
   - 与**未更新登记**的地址冲突（指明被占用的既有设备名）。
6. **冲突即禁止应用**：存在任一带错误的行（或表头无法识别、没有数据行）时「应用导入」按钮禁用；修正 CSV 后预览即时刷新，无需重新粘贴。
7. **原子应用**：全部通过后点击「✓ 应用导入」，一次性用合并快照**替换**主机登记状态——未在 CSV 中出现的登记原样保留（包括其自动 / 手动方式），被命中的登记整体更新，新登记以**手动**方式追加。应用后顶部提示新增 / 更新 / 无变化的台数；主机面板、dnsmasq 静态租约、反向 DNS、DHCP 地址池等所有读取登记的模块立即联动。
8. **规划变化后保留与重算**：原始 CSV 文本只保存在页面内存中，调整规划（网段迁移、改掩码、删除需求）后**不会丢失**，预览按新规划实时重算——原网段消失时相关行转为网段冲突并保持原文可见，恢复匹配网段后自动重新通过；输入非法（左侧规划错误）时面板暂停并保留 CSV。
9. **边界与隔离**：批量导入只通过 `hostAssignments` 与既有功能衔接，不修改规划、基线、路由汇总与 JSON 导出；载入示例 / 清空会一并清除 CSV 文本。

## 迁移执行编排

页面底部 **⑪ 迁移执行编排** 面板把「⑥ 主机地址分配」的现有登记与 **⑩ 静态租约批量导入** 的无冲突合并预览之间的差异，编排成一份可以照着逐步操作的改址清单（面板**纯只读**：不应用导入、不修改任何登记）：

1. **数据来源**：直接复用 ⑩ 的合并预览。CSV 尚未粘贴 / 表头无法识别 / 预览存在冲突（含表头错误或任一行标红）时，本面板**不生成任何步骤**，只提示先去 ⑩ 修正；预览无冲突（即使尚未点击「应用导入」）即开始编排。左侧规划输入非法时暂停，CSV 与登记原样保留。
2. **改动判定**：以登记稳定 ID 对齐现状与目标——地址不同的既有设备为**改址**，CSV 中的新 MAC 为**新增上线**，地址相同的「无变化」行不产生步骤。
3. **依赖图（以旧地址占用关系）**：若设备 X 的目标地址当前由改址设备 Y 占用，则 X 依赖 Y 先迁出。由此得到一张有向图：
   - **无环部分**按可执行顺序输出——每一轮在「目标地址已经腾空」的设备中取**目标地址最低**的一台执行，保证每一步的目标地址都不在线，故全程**不会产生瞬时重复 IPv4**；步骤原因中说明直接空闲可迁、或原占用者已迁出。
   - **互换（2 设备环）或多设备环路**（依赖图的强连通分量）需要临时锚点：在环中选一台设备（优先原地址最低、其**原网段**可用的设备），先迁到该网段内**最低的临时可用主机地址**。临时候选必须同时满足：不是网络 / 广播地址、**排除当前全部占用**、**排除全部设备的目标地址**，并避让此前为其他环路选定的临时地址。锚点腾空原地址后，环内其余设备按依赖顺序依次改址，最后锚点从临时地址迁到其目标地址，**临时地址自然释放**（环摘要区列出环构成、锚点设备、临时地址与所在网段）。
   - **阻止环路**：环中没有任何一台设备能在其原网段找到满足条件的临时地址时（典型：两台设备占满某个 /30 的 `.17/.18` 后互换），该环标记为已阻止并给出原因与网段可用范围；此时**整个迁移清单不输出任何步骤**，登记状态保持不变。
   - **无法腾空的目标地址**：目标地址被一台**不会迁走**的既有设备物理占住（例如一条失效的越界登记恰好落在新设备的目标地址上）时，作为阻断项点名该设备，提示先回主机面板改址或删除。
4. **新增设备**：新 MAC 设备在其目标地址腾空后才安排「新增上线」步骤（排在需要腾空该地址的改址步骤之后）。
5. **逐步展示与复制**：表格逐行给出**步骤序号、操作（临时迁出 / 迁移 / 完成环路 / 新增上线）、设备、原地址、目标地址、临时地址、目标网段与原因**；顶部汇总改址设备、新增上线、地址环路、临时迁出次数与总步数。「📋 复制清单」输出制表符分隔的纯文本（同样的八列 + 无瞬时重复的完成说明），可直接粘贴进工单或表格；存在阻断或没有步骤时复制禁用。
6. **实时重算与隔离**：CSV 文本、规划（网段迁移 / 改掩码）或主机登记的任意变化都由 React 记忆化**立即重算**（与 ⑩ 共享同一份合并快照，不会重复解析）。编排过程只读规划、登记与合并预览，**绝不修改登记**，也不影响规划、基线、路由汇总、导入状态与 JSON 导出；载入示例 / 清空会一并清除。

## IPv4 路径分片预演

页面底部 **⑫ IPv4 路径分片预演** 面板（紧随 ⑪ 迁移执行编排）按 [RFC 791](https://datatracker.ietf.org/doc/html/rfc791) 的规则在**纯本地**逐跳模拟一个 IPv4 报文的分片过程，不发送任何真实报文：

1. **发送设备**：下拉只列出「⑥ 主机地址分配」中**当前有效**的主机登记（显示设备名、IPv4 与所属网段，按 IPv4 升序）。登记被删除、改址失效或所属网段消失时，设备选择与全部参数录入**原样保留**，预演暂停并提示重新选择。
2. **输入参数**：负载字节数（整数 **1～65515**，总长度 = 负载 + 20 字节首部，不超过 IPv4 总长度字段上限 65535）、**DF 开关**（`DF=1` 禁止分片 / `DF=0` 允许分片）、按报文**经过顺序**排列的 **1～8 跳 MTU**（整数 **68～65535**，68 为 RFC 791 规定的最小 IPv4 MTU），支持增删与上移 / 下移调整跳序。
3. **逐跳处理**（固定 IPv4 首部 20 字节、无选项；每跳处理上一跳输出的全部分片）：
   - 分片总长度 **≤ 本跳 MTU**：**原样通过**，片偏移与 MF 完全不变；
   - 总长度 **> MTU 且 DF=1**：在该跳丢弃报文，报告**首个阻断跳**（跳序、MTU、报文总长度）并**立即停止**，后续跳不再执行；
   - 总长度 **> MTU 且 DF=0**：在本跳对该片**再次分片**（路由器只分不重组）——取不超过 MTU 的最大负载（MTU−20）并向下取整到 8 的倍数，**除覆盖原始负载末尾的子片（原始最后一片）外，每个子片负载必须是 8 的倍数**。
4. **偏移与 MF**：片偏移始终相对**原始负载**起点、以 **8 字节**为单位（再分片也不会重新归零）；`MF=1` 当且仅当该片之后仍有原始数据（负载末端未到达原始负载末尾）。
5. **逐跳展示**：每跳给出进入 / 输出片数与处置徽标（原样通过 / 发生分片 / 阻断），表格逐片列出**来源片负载范围、处置、输出片负载范围、负载字节数、总长度、片偏移（×8 字节）、MF**；底部统计**最终片数、首部开销（片数 × 20 字节）、全部片总长度合计**，并校验负载守恒（各片负载合计恒等于原始负载）。
6. **非法暂停与实时重算**：设备未选、负载越界 / 非整数、任一跳 MTU 为空 / 越界 / 非整数或跳数超出 1～8 时，错误**定位到具体字段（含第几跳）**并暂停预演，全部输入保留不丢；左侧规划输入非法时同样暂停。主机登记或规划的任意变化都实时重算设备清单与预演结果。

## 分配规则说明

1. 需求主机数 `h` → 网段大小取满足 `size − 2 ≥ h` 的最小 2 的幂，`size ≥ 4`，即前缀 `≤ /30`。
2. 先登记保留区和固定网段（校验包含性、互不重叠、固定段容量足够）。
3. 自动需求按所需前缀从小到大（规模大→小）排序；所需前缀相同时保留录入顺序。
4. 对每个需求，按地址升序扫描空闲间隙，取第一个能容纳该块、且起始地址对齐到其前缀边界的间隙；这就是「占用区之外的最低对齐空闲地址」。
5. 若所有间隙都无法容纳，报告：当前最大连续空闲块、所需块大小与前缀，或边界对齐不满足的原因；其余需求继续尝试分配（互不影响）。
6. 浪费量 = 自动/固定网段的（可用主机数 − 需求主机数）；保留区与空闲区不计入浪费统计。

## 基线对比规则说明

1. 每条需求在新增时生成稳定 ID，随输入编辑保持不变；对比按 ID 匹配，重命名不影响匹配。
2. 状态判定：同一 ID 的两个时点都是已分配时，CIDR 相同 → 未变（或纯容量变化）；CIDR 不同 → 迁移，并在容量同时变化时叠加扩容/缩容。已分配 ↔ 失败分别记为未分配 / 恢复分配；两侧均失败记为仍未分配。
3. 地址区间对比基于「保留 + 固定 + 自动」的占用集合：`仍占用 = 基线 ∩ 当前`，`新占用 = 当前 − 基线`，`释放 = 基线 − 当前`；区间经扫描线合并，重叠地址只计一次。
4. 净地址变化 = 新占用地址数 − 释放地址数，与「当前占用总量 − 基线占用总量」相等（同一父网段时）。
5. 基线仅允许在无输入错误时保存/重建；存在输入错误时保留基线、暂停对比；基线存于 `sessionStorage`，关闭浏览器即清除。

## 基线优先重排规则说明

1. 仅当 `baseline` 存在、当前父网段为规范 CIDR 且 `baseline.parentCidr === 当前父网段` 时引擎内重排逻辑才会激活；否则即使传入基线也走原算法，结果不含 `reflow`。
2. 目标前缀仍由 `prefixForHosts(当前主机数)` 得到；优先候选起点为 `alignTo(基线网络地址, 目标前缀)`——目标前缀下包含该地址的对齐块是唯一的。
3. 候选之间不做互换/试探：按「块大小降序、录入顺序升序」单次遍历，遇到可行即占位。因此保留的是字典序意义下「大块优先、早录入优先」的可行候选集合。
4. 固定网段与保留区视为静态占用：任何与之相交的候选直接拒绝；固定段需求本身不参与自动重排（报告中标注固定相关状态）。
5. 兜底阶段对未采纳需求复用原 `placeLowest`（间隙升序 + 前缀对齐），保证关闭/开启模式以外的分配语义不变；占用段在任何情况下都互不重叠且地址守恒。
6. 段级结果 `baselineOutcome` 只比较当前起点与基线起点（相同=kept，不同=moved），与是否经候选落位（`baselineAnchored`）正交：候选落位但起点改变为「原址迁移」，兜底落位也可能恰好回原址（「兜底保留」）。
7. 基线中未分配的需求恢复分配后标记「基线时未分配」（无优先候选）；基线后新增需求标记「新增」。这两类不计入优先候选采纳/被拒计数。

## 路由汇总规则说明

1. 勾选集合取当前规划中成功分配的固定 / 自动网段（均为彼此不重叠、且已对齐 CIDR 边界的网段）。
2. 将所选区间排序后，仅在**端点相接**（相邻）时合并；中间隔着任何未选地址（未选需求、保留区、空闲）都不会合并。
3. 对每个合并后的连续整数区间做最少 CIDR 拆分：从游标起取「起点能对齐、且不超过区间剩余长度」的最大 2 的幂块，逐块推进。该贪心得到的块数最少（区间到 CIDR 的经典分解）。
4. 聚合因此是安全且精确的：两个块被合并，当且仅当它们前缀相同、地址连续且同属一个上级网段（例如 `0/30` 与 `4/30` 合为 `0/29`）；跨上级边界（如 `4/30` 与 `8/30`）会在边界处拆成两个块。
5. 每个汇总块回查覆盖到的原网段，逐行展示其名称与 CIDR；汇总总地址数恒等于所选网段容量之和（无重复、无遗漏）。
6. 复制输出按网络地址升序、每行一个 CIDR；输入非法或没有成功分配网段时面板禁用；规划变化后自动剔除已不存在或分配失败的勾选。

## 主机地址分配规则说明

1. 可登记对象仅限当前规划中成功分配的固定 / 自动网段（以需求稳定 ID 关联）；规划只产生最小 /30，故每段可用主机范围恒为 `网络地址+1 … 广播地址−1`。
2. 自动取址从 `网络地址+1` 起升序扫描，取第一个不在该网段既有登记地址集合中的地址；网络地址与广播地址天然不在扫描范围内。
3. 手动输入依次校验：IPv4 文本合法 → 不是网络地址 → 不是广播地址 → 落在所属网段可用范围内 → 不与同网段其他登记重复；任一不满足即拒绝并展示具体原因。
4. 剩余可用数 = 网段可用主机数 − 该网段**有效**登记数；失效登记（越界 / 网络地址 / 广播地址 / 重复）不占用剩余数。
5. 重新规划后的去留只取决于地址本身是否仍合法：仍合法则按原 ID 原地址保留（任何模式都不静默改址）；不合法则保留登记并标记失效原因（需求删除 `owner-gone`、分配失败 `owner-unallocated`、越界、网络地址、广播地址、重复）。同地址重复时保留录入顺序最早的一条有效。
6. MAC 为可选项：录入时接受统一冒号或统一连字符分隔的六组两位十六进制，保存时归一为小写冒号；全零 MAC 与首字节最低位为 1 的组播地址（含广播）拒绝；MAC 在全部设备之间全局去重（编辑自身除外），故合法保存的任意两条登记不会有相同 MAC。
7. 主机登记（含 MAC）独立于规划引擎：不进入 `PlanResult`、基线快照、路由汇总输入与 JSON 导出，上述模块的计算结果在有无登记时严格一致。

## dnsmasq 静态租约规则说明

1. 租约视图对全部登记再跑一次当前规划校验（与面板相同的 `reconcile` 结果），只把**校验有效且 `mac` 非空**的登记放入输出。
2. 排除项及原因：失效登记 → `登记失效：<失效说明>`（需求删除 / 分配失败 / 越界 / 网络地址 / 广播地址 / 地址重复）；未填写 MAC → `未填写 MAC`；生成层另有一道重复 MAC 防御（异常数据下只保留录入最早的一条，其余原因 `MAC xx 与其他设备重复`）。
3. 输出行为 `dhcp-host=<小写冒号 MAC>,<点分十进制 IPv4>`，按 IPv4 数值升序；无条目时输出为空串，复制 / 下载按钮禁用。
4. 复制使用剪贴板 API（非安全上下文自动回退到隐藏 `textarea` + `execCommand`）；下载为浏览器端 Blob，文件名 `dnsmasq-dhcp-host-<UTC 时间戳>.conf`，全程不经过服务器。
5. 生成模块为纯函数读取：不修改规划、基线、路由汇总与任何既有 JSON 导出；规划或登记变化即由 React 记忆化重算实时刷新。

## DHCP Option 121 规则说明

1. 客户端网段只能取当前规划中成功分配的固定 / 自动网段（以需求稳定 ID 关联）；输入非法、无成功网段或所选网段失效（需求删除 / 分配失败）时暂停生成并保留全部录入。
2. 目的 CIDR 复用 `parseCidr(strict)`：必须是合法 `a.b.c.d/nn`、前缀 0–32 且为主机位全 0 的**规范网络地址**；`0.0.0.0/0` 明确允许。下一跳为合法 IPv4，且严格位于客户端网段 `网络地址+1 … 广播地址−1` 内（网络地址、广播地址即使数值在区间内也拒绝）。规范目的相同的条目从第二条起判为重复。
3. RFC 3442 单条编码：`[prefix, network[0..ceil(prefix/8)-1], gw0, gw1, gw2, gw3]`——即 `/0` 为 5 字节（无目的字节）、`/1~/8` 为 6 字节、`/9~/16` 为 7 字节、`/17~/24` 为 8 字节、`/25~/32` 为 9 字节。
4. 下发顺序为**前缀长度降序（最长匹配优先），同前缀网络地址数值升序**；合并字节为各条字节顺序拼接，配置行为 `dhcp-option=121,<逗号分隔十进制字节>`。
5. 任一录入条目无效（含重复目的）即**整体停止生成**：`optionLine` 为空、按钮禁用；错误按条目在全部行中的位置（1 基序号）逐条收集定位，目的与下一跳都为空白的占位行跳过、不占错误。行视图对自身无错的条目独立给出字节预览，不受其他错误条目影响。
6. 规划重算后面板按稳定 ID 重新执行同一套校验：录入文本绝不被静默改写；客户端网段迁移导致下一跳越界 / 成为网络或广播地址时实时报错，需求恢复分配或改选有效网段后自动恢复。
7. Option 121 状态（客户端选择与路由录入）独立于规划引擎：不进入 `PlanResult`、基线快照、路由汇总、主机登记与 JSON 导出，上述模块的计算结果在有无该状态时严格一致；载入示例 / 清空会一并清除。复制使用剪贴板 API（非安全上下文回退到隐藏 `textarea` + `execCommand`），下载为浏览器端 Blob 文件 `dnsmasq-dhcp-option121-<UTC 时间戳>.conf`，全程不经过服务器。

## 反向 DNS 区域文件规则说明

1. 网段只能取当前规划中成功分配的固定 / 自动网段（以需求稳定 ID 关联）；输入非法、无成功网段或所选网段失效（需求删除 / 分配失败）时暂停生成。仅支持 `/24` 与 `/25～/30`（规划只产生最小 `/30`，不存在更小可用网段）；大于 `/24`（如 `/23`）超出单个 in-addr.arpa 授权边界、`/31`、`/32` 无可用主机，均不支持并说明原因。
2. 记录来源 = `reconcileHosts` 结果中所属网段匹配且**有效**的登记；失效登记（越界 / 网络地址 / 广播地址 / 重复地址 / owner 失效）不进入任何区域文本，只在预览中列为「未读取」，既不参与 IP 排序也不阻断生成。
3. 设备名经 `classifyDeviceName` 分类：无点单标签（含空名、纯中文设备名）→ 静默跳过；多标签名称按 LDH 规则校验（标签 1–63、字母数字开头结尾、仅字母数字连字符、全名 ≤253、顶级标签非纯数字、ASCII）；允许恰好一个根尾点，输出 RDATA 统一为「小写、带根尾点」。
4. `/24` 区域名为网络地址前 3 字节反序 + `.in-addr.arpa`（`192.168.20.0` → `20.168.192.in-addr.arpa`），PTR owner 取 IPv4 末位字节。`/25～/30` 父区域为网络地址所在 /24 的同名区域，RFC 2317 子区域名为 `<起始末位>-<结束末位>.<父区域>`（`192.168.10.16/30` → `16-19.10.168.192.in-addr.arpa`）；父片段行 `<末位> IN CNAME <末位>.<子区域>.`，子区域文件行 `<末位> IN PTR <FQDN>.`。
5. 重复域名以「去根尾点、转小写」为键，只放过按 IP 升序首次出现者，其余逐条报错（指明与第几条重复）。任一名称错误都使**整体停止生成**：`zoneText` / `parentText` / `childText` 全部为空串、复制下载按钮禁用；无错的有效行仍在预览表中按 IP 升序可见。
6. 规划或登记任意变化（网段迁移、改掩码、登记增删、改名、改址）都经 React 记忆化重新执行同一纯函数；迁移后原址登记自动撤出，在新网段可用范围改址后自动恢复，任何登记文本都不会被静默改写。
7. 区域文本含 `$ORIGIN`、`$TTL 86400`、SOA（序列号默认当日 UTC `YYYYMMDD00`，7200/3600/1209600/3600）与 NS 占位（`ns.example.com.`、`hostmaster.example.com.`）；RFC 2317 父片段额外以注释给出 `<起>-<止> IN NS <服务器>` 委派模板。这些均为占位值，部署前必须替换。
8. 反向 DNS 状态（仅所选网段 ID）与生成过程独立于规划引擎：不修改 `PlanResult`、基线快照、路由汇总、主机登记与 JSON 导出，上述模块的计算结果在有无该面板时严格一致；载入示例 / 清空会一并清除选择。下载为浏览器端 Blob（`<区域名>-<UTC 时间戳>.zone`），全程不经过服务器。

## DHCP 动态地址池规则说明

1. 宿主网段只能取当前规划中成功分配的固定 / 自动网段（以需求稳定 ID 关联）；输入非法、无成功网段或所选网段失效（需求删除 / 分配失败）时暂停生成并保留网段选择与全部排除录入。
2. 候选地址空间恒为宿主网段的可用主机范围 `网络地址+1 … 广播地址−1`：网络地址与广播地址由模块自动排除，手工区间即使覆盖它们也不会额外减少可分配数量（规划只产生最小 `/30`，每段至少 2 个可用主机）。
3. 自动排除的主机登记取 `reconcileHosts` 结果中所属网段匹配且**有效**的地址；失效登记（越界 / 网络地址 / 广播地址 / 重复 / owner 失效）不参与扣除。
4. 手工排除区间逐条校验：起始必填且为合法 IPv4；结束留空视为与起始相同（单地址排除），填写时必须为合法 IPv4；结束不得小于起始（起止有序）；两端均须位于宿主网段 `网络地址 … 广播地址` 闭区间内。起止都空白的占位行跳过。
5. 手工区间先经区间合并（重叠或端点相接即合并，复用基线模块的 `mergeRanges`），再与有效主机登记地址合并去重；因此重叠 / 相邻项与登记地址都不会重复扣除。
6. 剩余地址 = 在可用主机范围内按地址升序扫描、逐段扣除合并后的排除集合，得到若干**互不重叠、连续且非空**的整数区间；每段输出 `dhcp-range=<点分起始>,<点分结束>,<点分掩码>`，掩码由宿主网段前缀经 `prefixMask` 换算（如 `/27 → 255.255.255.224`）。段数量为区间内地址总数（含首尾），总数为各段之和；全部地址被排除时池为空、不输出配置。
7. 任一录入条目无效即**整体停止生成**：`pools` / `configText` 为空、复制下载按钮禁用；错误按条目在全部行中的位置（1 基序号）逐条收集定位（越界区间起止分别报错）。行视图对自身无错的条目独立给出区间预览，不受其他错误条目影响。
8. 规划、登记或排除项任意变化（网段迁移、改掩码、登记增删改址、排除区间增改删）都经 React 记忆化重新执行同一纯函数；迁移后原排除录入原样保留并按新网段重新校验，绝不静默改写。
9. 动态地址池状态（宿主网段 ID + 排除区间录入）独立于规划引擎：不进入 `PlanResult`、基线快照、路由汇总、主机登记与 JSON 导出，上述模块的计算结果在有无该状态时严格一致；载入示例 / 清空会一并清除。复制使用剪贴板 API（非安全上下文回退到隐藏 `textarea` + `execCommand`），下载为浏览器端 Blob 文件 `dnsmasq-dhcp-range-<网段>-<UTC 时间戳>.conf`，全程不经过服务器。

## 静态租约批量导入规则说明

1. CSV 由内置解析器处理：支持引号包裹字段、字段内逗号/换行与 `""` 转义；自动去除 BOM、识别 CRLF/CR/LF；完全空白的物理行跳过。首行必须是表头，四个必需列按「去空白、转小写」后的别名表识别（网段 CIDR / 设备名 / IPv4 / MAC），缺列或同一列匹配到多个表头时给出表头级错误且不产生数据行预览。
2. 网段字段经 `parseCidr(strict)` 解析为规范 CIDR 后，在当前规划的成功分配网段（固定 / 自动，互不重叠、CIDR 唯一）中精确匹配；保留区、空闲区与失败需求不匹配。设备名去首尾空白后不可为空；IPv4 经 `ipToInt` 解析；MAC 经 `normalizeMacInput` 规范化（本模块中 MAC 必填，因为它是设备身份）。
3. 合并快照 = 未被任何导入行按规范 MAC 命中的既有登记（原样复制）+ 每个字段全部解析成功的导入行（命中既有 ID 则整体替换其 `ownerId/name/address/mac` 并置 `mode='manual'`，否则以新稳定 ID 追加）。字段解析失败的行不进入快照，但仍在预览中标冲突。
4. 顺序无关性来自「先合并、后校验」：地址重复检测在合并快照上按 `网段 ownerId#地址` 单次扫描取最早一条，互换地址的两行都已在快照中，故二者都有效；单向迁入未更新设备占用的地址时，迁入行被后扫到而判冲突（原因中给出未更新设备名）。输入内重复 MAC / 重复 IP 在逐行解析阶段即时检测并指明首次出现行号，与合并快照检测互为补充。
5. 行状态：自身存在任一错误（字段、网段、网络/广播/越界、输入内重复、合并快照冲突）即为冲突；无错且命中既有 MAC 时，名称 / 网段 / 地址全同记为无变化，否则记为更新；无错且未命中 MAC 记为新增。
6. 可应用条件：表头识别成功、至少一条数据行、冲突行数为 0。应用是一次 `setHostAssignments(merged)` 原子替换，不存在逐行落库的中间状态；不满足条件时 `merged` 回退为既有登记的副本，外部状态不会被部分改写。
7. CSV 文本保存在页面内存（与 Option 121 录入、排除区间等相同的生命周期）：规划、登记任何变化都由 React 记忆化重新执行同一纯函数 `buildLeaseImport`；载入示例 / 清空会清除 CSV。模块不修改 `PlanResult`、基线、路由汇总与 JSON 导出。

## 迁移执行编排规则说明

1. 编排入口 `buildMigrationPlan(imported, existing, result)` 的 `imported` 必须是 `buildLeaseImport` 的结果；仅当 `canApply=true`（表头识别成功、有数据行、零冲突）时才计算，否则直接返回 `ok=false` 的 `pending` 阻断项，不产生步骤。面板与 ⑩ 共享 App 层 `useMemo` 出的同一份 `LeaseImportResult`，CSV / 规划 / 登记任一变化两者同时重算。
2. 设备以登记稳定 ID 在「现有登记」与「合并快照」间对齐：既有 ID 且地址变化 = 改址（记录原地址与原网段）；仅出现在快照中的新 ID = 新增上线；地址相同不产生步骤。目标网段取快照登记 `ownerId` 对应的成功分配网段（无冲突预览保证其存在）。
3. 迁移前物理占用按地址数值全局建表（跨网段同址不可能，规划段互不重叠）；异常重复登记全部纳入占用集合。设备 X 的目标地址上若有改址设备 Y，则建立依赖边 X→Y；若占用者不迁走（含失效的未更新登记），记为 `occupied` 阻断并点名设备，清单完全不输出。
4. 依赖图中的环由迭代式 Tarjan 强连通分量识别（仅改址设备参与；自环因原址=目标已在改址筛选中排除）。环按环内最小原地址升序处理，保证输出确定性。
5. 每个环选一台临时锚点：候选为环中「原地址处于某成功分配网段可用主机范围内」的设备，按原地址升序、ID 次序排序；临时地址在该原网段内从最低可用主机地址扫描，候选须不属于网络 / 广播地址，且不在「当前全部占用 ∪ 全部目标地址 ∪ 此前各环已选临时地址」集合中。任一候选都无空地址时该环标记 `blocked`、给出网段可用范围与全部尝试原因，整体 `ok=false`、步骤为空。
6. 执行模拟分三阶段，始终维护「当前在线地址 → 设备」集合并在每步迁入前断言目标地址无其他设备：①全部锚点临时迁出（腾空其原地址）；②循环取目标已腾空设备中目标地址最低者执行普通迁移，锚点设备执行「完成环路」（从临时地址迁入目标，临时地址随即释放）；③新设备按目标地址升序上线。任何时刻同一 IPv4 至多被一台设备占用（无瞬时重复），最终占用与合并快照一致、全部临时地址均释放。
7. 步骤类型 `temp-move / move / cycle-complete / add` 各自携带原地址、目标地址、临时地址（仅锚点相关步骤）、目标网段 CIDR 与面向操作人的中文原因；复制文本为「步骤/操作/设备/原地址/目标地址/临时地址/目标网段/原因」八列制表符分隔，附完成说明行。
8. 编排为纯函数只读：不修改 `existing`、`imported.merged`、`PlanResult`、基线、路由汇总、主机登记与 JSON 导出（冒烟测试断言入参与规划结果字节不变）；面板自身状态仅有复制反馈。
## IPv4 路径分片预演规则说明

1. 核心逻辑位于 `src/lib/fragmentation.ts`，为纯函数、纯本地计算：输入「负载字节数 + DF + 逐跳 MTU」，输出每跳与最终的结构化分片结果；不发起任何网络请求，也不读取或修改规划、基线、主机登记（主机登记只经 `reconcileHosts` 只读校验后提供有效设备清单 `listValidDevices`，按 IPv4 升序）。
2. 常量：固定首部 `IPV4_HEADER_LEN=20`（IHL=5、无选项）；负载合法范围 1～65515（总长度 = 负载 + 20 ≤ 65535）；跳数 1～8；单跳 MTU 合法范围 68～65535 的整数（68 = RFC 791 最小 IPv4 MTU）。文本输入为空 / 非整数 / 越界均判非法，**不做夹取、保留原文**；`validateFragInput` 按「设备 → 负载 → 逐跳 MTU（带 1 起跳序号）」返回可定位错误，任一错误存在即不执行预演。
3. 模拟从发送设备处的单个原始报文开始（`originalDatagram`：负载 0…L、offset=0、MF=0、总长度 L+20）。每跳遍历上一跳输出的全部分片：总长度 ≤ MTU 原样通过（偏移 / MF 不变）；超过 MTU 时，DF=1 即在**首个**这样的跳阻断（记录 `blockedHopIndex` 与被丢弃片）并立即终止；DF=0 则由 `fragmentPiece` 拆分。
4. `fragmentPiece` 取 `maxPayload = MTU − 20`，从片负载起点顺序切分：除「子片末端到达原始负载末尾」的最后子片外，每段负载向下取整为 8 的倍数（进入每段的起点恒为 8 对齐）；子片 `offset = 负载起点 / 8`，`MF = (子片末端 < 原始负载长度)`。因此再分片后偏移仍相对原始负载，且**路由器只可能继续分片、片数单调不减，绝不重组**。
5. 结果 `FragResult` 含每跳 `FragHopOutcome`（进入 / 输出片数、每片通过或拆成哪些子片、阻断信息）与最终分片；统计片数、首部开销 = 片数 × 20、全部片总长度合计（= 原始负载 + 首部开销）。冒烟测试断言任意多级 MTU 路径下各跳输出片负载**首尾相接、不重不漏、合计恒等于原始负载**、偏移 8 字节对齐、且每跳恰好只有覆盖原始末尾的一片 MF=0。
6. 面板 `src/components/FragmentPanel.tsx` 的设备选择、负载、DF 与逐跳 MTU 文本保存在 App 层状态（载入示例 / 清空一并重置为默认的单跳 MTU 1500、负载 1400）。规划输入非法、已选设备失效（登记删除 / 改址失效 / 网段消失）或字段非法时仅**暂停渲染结果**，选择与全部输入原样保留；主机登记、规划、DF 或任一参数变化都经 `useMemo` 实时重算。
